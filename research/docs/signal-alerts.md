# 新信号提醒与 OKX 实时更新

在 **AI选币 → OKX实时** 中，先选好看多/看空、MACD类型、涨跌幅等条件，再点击“开启声音提醒”和需要时的“开启桌面通知”。声音需点击激活，桌面通知需浏览器授权。保持页面打开；关闭页面后不会提供系统后台推送，移动浏览器休眠也可能延迟。

- 新信号按当前分类和筛选条件提示，置顶并标记“新信号”。同一信号的价格更新不会再次报警；“标为已读”清除高亮。
- 首次加载列表、首次采集某个币种、历史补采不报警。更换筛选条件不会把已经加载过的旧信号再次提示。
- “推荐时间”是历史K线计算出的条件起点，不表示本站当时已发出通知。“信号确认时间”是首次观察该信号时使用的已收盘K线时间；“本站首次发现”才是本站实际计算发现的时间。“发现时价格”会保留，不随当前价格变化。
- MACD出现新交叉时会建立新的事件；趋势延续或历史窗口滚动不重置首次发现时间。
- 后台的信号标识及首次发现记录存入SQLite；个人浏览器的已见记录、未读高亮和开关保存在本地。SQLite需要持久磁盘才能跨Render重新部署保存。
- 已订阅均线、趋势或放量站内通知的注册用户，也会收到相应新事件的站内消息。没有调用邮件、Telegram或交易接口。

## 实时通道

服务默认为OKX启用公开 `wss://ws.okx.com:8443/ws/v5/business` 的 `candle3m/candle5m/candle15m`。REST先为每个币种预热历史；只有完成预热的币种才订阅实时K线，不能跳过EMA200等指标所需历史。订阅操作分批发送，连接断开后退避重连。

仅处理交易所标记已收盘的K线。未收盘、重复、未知币种和错误数值会忽略；缺失K线时暂停该币种实时计算，按币种触发少量REST补采后恢复，避免等待完整全量扫描，也避免跨缺口计算。补采共用上游请求预算与封禁冷却，失败后延迟重试。

网页使用本站 `/api/market/events` 的SSE通道接收结果变更通知，再读取本站缓存，不请求交易所。SSE不可用时仍每60秒读取结果。价格独立任务和REST补采继续运行；`OKX_REALTIME=0`可关闭上游WebSocket。

`/api/market/status` 的 `realtime.connected` 表示连接状态，`realtime.symbols` 为已预热待订阅币种数，`lastClosedCandleAt` 表示实际收到的收盘K线时间，`pendingRecovery` 表示等待补齐的币种数。仅连接建立不等于全量已预热或已验证实时信号。

实时连通性需要在部署环境实际验证。开发环境的WebSocket连接未能建立；受控测试用于验证计算、补齐、去重和提醒逻辑。另于2026-10-16在hjs-3实际验证OKX连接成功，并收到北京时间22:20的收盘消息，返回信号已有`okx-websocket`计算标记。连接状态以后仍应以线上状态接口为准。

验证：`npm test`、`npm run build`、`node tests/signal-alerts-browser.mjs`。
