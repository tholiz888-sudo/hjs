# 真实账户接入：邮箱登录账户

当前阶段是逐笔确认的小额限价单连接器，不是自动盈利机器人。模拟任务不会调用真实下单接口。实盘默认关闭，尚未使用用户账户完成认证、下单、撤单或结算验证。不要把页面显示的模拟资金视为实盘余额。

## 已确认的测试约束

用户已选择：总额度25美元、单笔最多2美元、每日最多亏5美元。代码硬限制为累计25美元、单笔本金加保守手续费预留最多2美元、北京时间每日5美元的累计风险预算。这比按每日净亏损统计更保守；撤单、退款、盈利后均不自动返还预算，没有网页重置预算接口。

仅支持当前已开始且剩余至少210秒的BTC 5/15分钟Up/Down市场；GTD到期至少190秒后，post-only限价挂单，不允许市价单。为防SDK偷偷增加额度，签名后再次核验合约、maker、买入方向、份额、本金、到期时间和post-only属性。若平台最小份额使单笔超过2美元，直接拒绝，不自动加钱。挂单可能完全不成交，不保证能在市场结束前获利或退出。

## 官方SDK依据

使用 `@polymarket/client@0.16.0` 和 `viem@2.46.3`，锁文件固定解析结果。官方原clob-client仓库已声明归档且客户端不再可用，不使用旧客户端或根据“邮箱登录”硬编码旧signatureType。

- https://github.com/Polymarket/ts-sdk/tree/main/packages/client
- https://github.com/Polymarket/ts-sdk/tree/main/examples/scripts
- https://github.com/Polymarket/clob-client

核对日2026-11-03。SDK鉴权使用已审阅的beginAuthentication工作流（SDK标为内部低层接口，因此固定版本、受测试约束），只允许获取地址及认证typed-data签名，避免createSecureClient可能自动部署默认钱包。SDK返回账户必须匹配配置地址且signerType=OWNER；未验证session key和其他钱包类型不猜测兼容。连接可能创建或派生交易API凭证，但不提交订单、链上批准、转账、合并或部署。API凭证只留进程内，不显示、不写日志和磁盘。

这不是Polymarket邮箱登录OAuth：邮箱或邮箱密码不能签交易，当前页面不会收集它们。用户需要通过平台当前官方支持的签名/导出/授权流程取得账户授权；无法验证支持时保持关闭。不要根据第三方教程进入非官方私钥导出站点。尽量使用仅存小额测试资金的账户；导出的主签名私钥有广泛账户权限，本程序内额度限制不能限制私钥在别处的能力。

## 先确认公开账户，再安全配置

先核对自己的Polymarket个人主页公开地址与资金账户地址，不要填bosona的钱包地址。配置名称如下（只在你控制的部署平台加密环境变量中设置，不在聊天、Git、浏览器输入框或日志中填写秘密）：

| 变量 | 内容 |
| --- | --- |
| LAB_ADMIN_TOKEN | 已有管理口令，保护实盘状态、账户信息及全部操作 |
| POLY_FUNDER_ADDRESS | 用户自己的Polymarket资金账户公开地址；不根据邮箱猜测 |
| POLY_SIGNER_PRIVATE_KEY | 平台支持的账户签名者私钥；必须与资金账户实际匹配。不要在聊天提供；未确认安全授权方式前不要填 |
| LIVE_DATA_DIR | 实际持久磁盘内的独立目录，例如已挂载磁盘下的 `/var/data/polymarket-live` |
| LIVE_TRADING_ENABLED | 初始设为 `0`；仅在账户验证、持久磁盘和预览均通过后，账户持有人自行开启为 `1` |

LIVE_DATA_DIR只表示路径配置，不证明磁盘持久性。必须在Render设置中确认该目录位于已挂载持久磁盘；不能用免费实例临时目录冒充。备份SQLite及WAL文件需使用SQLite一致性备份方式。程序不会购买实例、磁盘或转入资金，也不会替用户设置凭证。

Render原服务的Build Command需改为 `npm ci && npm test`，Start Command仍为 `npm start`。官方SDK现在有npm依赖，旧的“无需安装依赖”仅适用于此前模拟版。Node.js 24.19.0及HOST配置保持原样。启动命令使用Node `--use-env-proxy`，保留已有代理与TLS验证。

## 页面操作

1. 部署后使用HTTPS打开页面，在顶部输入管理口令。
2. “真实账户”区域点击“检查接入配置”，只显示配置存在与否。
3. 点击“验证账户连接”，核对资金账户、签名者、钱包类型、余额及只允许平仓状态。可能创建/派生API鉴权凭证，不会下单或增加链上授权。返回错误不证明需要新钱包；先诊断当前授权与网络。
4. 填市场slug、Up/Down、限价和份额，点击“生成订单预览”。合约必须由官方市场数据映射，不能由用户任意填token。预览30秒有效。
5. 确认所有信息后，才在环境设置打开真实提交开关、重新部署，然后重新预览。输入明确文字“确认提交真实买单”，点击“提交这笔真实买单”。该按钮是真实资金操作；未连接Fisher自动信号。
6. 记录平台订单ID，通过“查询核对”查看部分成交，用“撤销此订单”取消剩余挂单。取消不撤销已成交份额；平台拒单不等于网络超时。

数据库SQLite同步持久化订单意图，在发送前原子占用预算，同一预览只允许发送一次。不依赖客户端禁用按钮防重。网络超时、响应未知或重启中断转为UNKNOWN，保留预算且禁止新单；不自动重发。无订单ID的UNKNOWN须在平台活动/订单中人工核对，不盲猜。数据与所配置资金账户绑定，不允许在同一账本偷偷更换账户。

“紧急停止新单”持久化禁止后续买单，但不自动撤单、卖出或清空已有仓位；在途请求可能已发出。仍应逐单取消并到平台核对。页面没有解除紧急停止或清空额度按钮。后续若需恢复，应先核对账本和账户，再单独审查维护操作。

## 费用和限制

本版只挂post-only单，另按官方SDK当前费率模型 `size × rate × [p(1-p)]^exponent` 在所有价格上的最大值预留费用。rate/exponent来自市场接口，缺失或异常即拒绝。没有builder fee；新费率语义变化、额外费用或链上资金操作不在支持范围。源码未自动开任何代币授权，若已有交易授权不足，下单会被平台拒绝；不能自动执行SDK placeLimitOrder的allowance recovery。

只控制本程序的测试订单预算，不限制同账户在其他网站/设备的操作。还没有真实自动补仓、合并、赎回、按即时市值计算每日损失或无人值守全天实盘。现有Fisher信号未经盈利验证，不能直接开启自动真实投注。

## 当前验证范围

单元/集成测试模拟了拒单、限额、重复提交、撤单、未知响应、进程恢复和紧急停止；实际官方SDK使用公开测试密钥、假网络响应完成了本地GTD/post-only签名测试，没有发送真实订单。云环境未配置用户签名授权，平台网络亦有限制，因此用户账户连接、平台实际订单接受、成交和撤单尚未验证。不得将测试通过表述为实盘已准备完成。
