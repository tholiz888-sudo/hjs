# Polymarket 双边策略研究台

独立研究与模拟应用，Node.js 24，无 npm 外部依赖。不连接钱包，不发送真实订单；不是 bosona 策略的复刻，也不承诺收益。不改变仓库其他应用。

## 启动

```sh
cd /workspace/hjs/polymarket-lab
npm test
npm start
```

本机浏览器打开 http://127.0.0.1:3080 。Windows 在本目录运行 `npm start` 亦可。端口用 PORT 覆盖，默认仅监听本机；需要远程部署时由维护者自行配置 HOST 和访问控制。

点击“加载演示数据”，再“运行回放”。演示含正常配对、无优势拒绝、第二边失败及亏损结算。人工演示不是历史行情，不作为策略有效性的证据。参数、盘口及结果均可导出；页面刷新不保存数据，重要记录请导出。

## 数据格式

导入 JSON 数组；参考 public/demo.json。每条快照：

- market：同一组互补 Up/Down 合约的唯一标识，不能混用不同周期。
- time：盘口源时间，ISO 8601，所有记录按源时间升序，同市场时间戳不得重复。
- observedAt：收到盘口的时间，不能早于 time；差值用于拒绝旧报价。
- end：市场结束时间；同一 market 必须一致。
- up / down：卖盘数组 `[[价格,可买份数], ...]`，价格为0～1之间的小数，自动按从低到高排序。空数组表示没有流动性。
- secondLegFails：可选 true，注入 Up 买到后 Down 未成交的情形。
- winner：可选 `up` 或 `down`，只在实际确认结算后提供，此条不交易。observedAt 必须不早于 end。时间到期本身不代表胜者已确认。

引擎遍历卖盘深度，计算两边完整目标数量的成本，加入比例费用及不利滑点；低于最低净优势、深度不足、现金不足、单市场累计成本超限、第一边成交后全账户风险超限均拒绝。已消费盘口不能重复导入。不会用未来 winner 提前决定交易。

风险按未结算成本减去等量双边结算兑付下限估算，最低0。未配对仓位不计资产价值，因此保守权益可能低于即时市场价值。已结算净盈亏、现金、未结算成本分开显示；仅在输入结果后释放资金。不处理撤销市场、拆分/合并仓位、卖出、返佣和提款。

## 公开行情

输入 **市场 slug**（市场页面网址的最后一段，不是账户链接），采集一次公开盘口。通过固定 Gamma API 查询市场、核对 Up/Down token，再从 CLOB 读取两边卖盘；保留源时间，使用较早一边的时间作保守年龄判断。不会自动下单，不需要密钥。采集不是原子快照，真实成交仍可能失败。

需系统 curl，沿用代理和 TLS 校验；需可访问 gamma-api.polymarket.com 与 clob.polymarket.com。当前云环境这些目标未在网络白名单中，外部采集未验证成功。出错会显示真实错误，不用演示行情冒充。采集为手动单次；长期采集、钱包完整流水分析与实时自动策略不属于本版。

## 模型局限

费用是用户配置的“成交金额 × bps”近似，**不是 Polymarket 实际费率公式**；应按目标市场核对，否则结果不能用于实盘决策。滑点也是假设，未模拟排队、撮合延迟和其他交易者。平时两边成功成交是模拟假设，失败场景用于压力测试，不能当作无风险套利。

engine.mjs 另含可单测的 Fisher 指标（滚动收盘价格范围、平滑与截断），尚未接入BTC实时行情或方向策略，不是帖子未公开参数的精确实现。

## 验证

`npm test` 验证深度、费用、双边结算、第二边失败亏损、风险限制、数据校验、Fisher 和 HTTP 回放。验证不证明实盘可成交、账户收益属实或策略存在可持续优势。

## 部署到 Render

将本目录完整提交并推送到你的 GitHub 仓库。不要改动仓库根目录原有 render.yaml，它属于其他网站。

在 Render 选择 New → Web Service，连接该仓库、选择包含本模块的分支，填写：

| 设置 | 值 |
| --- | --- |
| Runtime | Node |
| Root Directory | `polymarket-lab` |
| Build Command | `npm test` |
| Start Command | `npm start` |
| Environment: NODE_VERSION | `24.19.0` |
| Environment: HOST | `0.0.0.0` |
| Health Check Path | `/healthz` |

PORT 使用 Render 自动注入的值，不必手动设置。若采用 Blueprint，指定仓库内的 Blueprint Path 为 `polymarket-lab/render.yaml`（rootDir 仍相对仓库根目录）。本配置选择 free 方案，实际可用性和费用以 Render 页面为准。

部署完成后打开 Render 分配的 HTTPS 地址，加载演示数据并运行回放；检查 /healthz 返回 status=ok。HTTPS 同源回放接口可用，无需自行关闭浏览器安全策略。

Render 的网络与当前云环境不同，当前环境403不等于 Render 也会403；真实采集必须在部署后另测。公开采集需要系统 curl 和允许目标域名连接。若仍失败，以界面错误和服务日志排查，不能绕过目标服务地区或访问限制。

该版本不保存账户、盘口与结果到服务器，浏览器刷新或免费实例休眠不会保留未导出的数据。请及时导出。免费实例可能休眠、首次加载较慢，不适合连续行情采集或无人值守交易。公网版本任何访客都可使用模拟及只读采集；不配置私钥，不用于实盘。正式长期运行前另行增加访问控制、限流和持久存储。

Render 平台通过 RENDER=true 或 RENDER_SERVICE_ID 自动识别，强制监听 0.0.0.0 并读取 PORT，无需手动设置 HOST（旧的 localhost HOST 也不会阻止绑定）。本地仍默认只监听 127.0.0.1。启动日志显示实际监听地址。

## 持续自动模拟（新版）

页面顶部“持续运行”区域为独立模拟账户。Render → Environment 添加 `LAB_ADMIN_TOKEN`，自行生成一个较长随机管理口令（不要使用钱包私钥或交易所密钥），保存并重新部署。在页面输入同一口令，点击“开始自动模拟”。未设置或口令不符时不能启动、停止或导出。口令不写入浏览器本地存储，刷新后需重填；请只通过 HTTPS 使用。

每30秒扫描未来一小时到期的部分 BTC/ETH/SOL/XRP 5分钟、15分钟 Up/Down 市场，每轮最多扫描300个市场、采集8个候选；有限扫描可能漏掉市场。持续模拟固定使用引擎默认参数（1000美元模拟资金等），下方手动回放参数不影响自动账户。每次按快照卖盘假设成交，不模拟真实挂单队列，也不复现 bosona 的分时配对，不能据此验证可执行盈利。行情变化中第二边失败概率未实测，实盘前必须增加真实延迟和成交校准。

到期后查询 Gamma，只有 `closed=true`、`umaResolutionStatus=resolved` 且两个结果价格明确为1/0时才记结算；其他状态保留待确认，不猜测赢家。源数据字段变更可能导致结算暂不识别，需要按官方文档调整适配。状态页显示现金、已结算盈亏、未结算成本、未配对风险和最近错误。状态与模拟结果可公开查看，不存私密交易数据；控制及完整导出需管理口令。

记录原子写入 `polymarket-lab/.local/paper.json`，可通过 `LAB_DATA_DIR` 指向持久磁盘目录。重启读取原记录，但默认停止，需再次手动启动。达到约5000条时停止而不裁剪仓位。导出的自动记录是包含 snapshots/config/markets 的完整对象；手动回放需要取其中 snapshots 数组，并使用相同 config。不要混合不同实验。

免费 Render 服务会休眠，普通定时器不会阻止平台休眠；休眠、重部署或崩溃期间不会采集，不伪造补齐数据。免费文件系统也不保证跨部署保留。真正全天运行需要用户自行选择常驻实例和持久磁盘，可能收费；本次没有购买资源。当前云网络仍无法验证 Polymarket API，因此自动模式仅完成模拟接口测试，需在 Render 看到真实采集计数增长后才算联网成功。
