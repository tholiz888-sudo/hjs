# 功能补齐与启用说明（2026-10-17）

本次保持现有前台样式，新增操作沿用现有按钮、表单和弹窗。新增后台入口为 `/admin?tab=operations`（“会员与服务”）。数据库仍使用现有SQLite，未迁移存储、未新增备份。

## 会员订单

1. 管理员在“会员与服务”填写套餐、有效天数、实际价格、收款说明，开启会员购买。
2. 管理员填写收款方式、币种、账号、收款人和银行／转账网络。用户登录后点击“会员与订单”，看到对应账号后创建订单并在外部完成付款，再上传PNG/JPEG/WebP付款截图（不超过2MB），交易编号可另填。订单只展示与套餐币种匹配的收款账号；账号随订单保存快照，避免后续修改影响审核。截图仅订单本人和管理员可查看，不会生成公开文件链接。
3. 管理员必须在自己的收款账户核实实际到账，确认后审核开通。应用不会替管理员验证银行或链上转账。
4. 订单创建时固定价格和天数，前台不能修改。重复审核不会重复开通，同一凭证不能重复用于已批准订单。会员按到期时间自动失效，续费从当前未过期的有效期继续延长。
5. 原用户管理中手工设置的VIP角色仍是长期授权；付费订单使用独立的到期记录。管理员邮箱仍可直接查看本站内容。
6. 可配置多档积分兑换会员，独立于付费购买开关；默认15天960分、7天480分、3天240分、1天120分。后台可增删档位、调整名称、天数和积分成本；前台个人中心“积分兑换”展示。普通注册用户和已有VIP均可兑换，现有未到期有效期继续延长；扣积分、流水及延长会员使用同一数据库事务。

这里未接入自动扣款、自动退款或发票服务。人工收款不应被宣传为自动支付；套餐默认关闭，默认示例价格须由管理员自行确定。

## 策略自动状态跟踪

在手动策略编辑中开启“自动目标／止损跟踪”，可选“目标1后保护止损推至入场价”。仅支持当前交易所已采集、且代码匹配的合约，不会替美股和贵金属虚构行情。

- 使用发布／开始跟踪之后的**完整已收盘5分钟K线**，不倒推发布前盈利。
- 按多空方向判断高低价触达，保存已处理时间，避免重复通知。
- 同根K线触及目标和止损无法确定先后：保守记录止损并显示歧义提示；不是实际成交记录。
- 目标1后的入场保护从下一根K线开始生效；同根K线内部先后不可推断。
- 修改方向、价格或重新开启跟踪时从当前时间重新开始，防止将新规则套用到旧行情。只编辑备注保留已处理进度。
- 历史存在缺口时暂停判断并提示，不能据此推断缺口期间是否止损。核对后可关闭、再重新开启跟踪。
- 这些状态是**价格触达记录**，不代表用户真实开仓、成交价、手续费或实现收益，没有自动交易功能。

## 邮件通知与找回密码

Render Environment 配置：

```text
RESEND_API_KEY=<在Render安全填写>
MAIL_FROM=<Resend已验证发件地址>
```

后台“会员与服务”开启邮件通知。用户须在推送设置验证收件邮箱，选择订阅主题并开启邮件通知。邮件验证码、密码找回可在服务密钥配置后使用；密码找回统一回应避免泄露账号存在性，有频率限制、验证码尝试次数限制、失效和一次性消费，重置后旧会话全部失效。

新文章、手动策略通知和新信号可进入邮件队列。队列按用户／渠道／事件去重；最多重试5次，指数退避，失败可在后台重试。信号通知超过10分钟会取消投递，避免休眠恢复后将旧信号当作新提醒。外部邮件服务超时后可能已经投递，因此网络重试不保证收件箱绝对不重复。

## Telegram通知

Render Environment 配置以下变量，勿把密钥填写在页面、Git或聊天中：

```text
TELEGRAM_BOT_TOKEN=<BotFather生成的机器人令牌>
TELEGRAM_BOT_USERNAME=<机器人用户名，不带@>
TELEGRAM_WEBHOOK_SECRET=<随机Webhook校验密钥>
```

按Telegram官方 `setWebhook` 接口，将Webhook设置为本站HTTPS地址 `/api/telegram/webhook`，并使用相同的 `secret_token`。本次未替用户创建机器人或注册Webhook。

后台启用Telegram，用户在推送设置点击绑定，通过10分钟有效的一次性链接，在机器人**私人聊天**点击Start。只有正确Webhook密钥和私人聊天消息能完成绑定，用户还需勾选Telegram通知与信号主题。解除绑定立即停止后续投递，不使用用户随意填写的Telegram用户名直接发送。

## AI问答

Render Environment配置 `OPENAI_API_KEY`；后台设置有权限使用的模型名称并开启AI问答。浮动AI面板点击“向AI提问”。默认模型名称是示例，需与账户权限匹配。

服务固定调用OpenAI HTTPS接口，不允许用户任意配置请求目标。每个用户每小时最多20次，全站默认每天200次（后台可调）；只传入问题及行情连接状态／指标配置，不传用户邮箱、密码、会员订单等数据。模型回复按纯文本显示。未经真实服务密钥验证前，仅能确认接入代码及受控测试，不能宣称真实模型已启用。

## 数据模块

- **OKX多空比**：接入官方公开币种合约账户多空比，默认BTC、ETH、SOL、XRP、DOGE、ADA、LTC、BCH、LINK、DOT；接口不支持或没有新数据的币种不伪造。共享5分钟缓存、请求节流和错误冷却。不受本站初次K线预热完成与否限制。
- OKX比率是按币种跨合约汇总；多空账户比例由真实比值换算。它与Binance单合约统计不完全相同，不提供大户真实开仓均价、价值或成本偏离值。币种范围有限，不冒充全部合约支持。
- **KOL**：后台录入或导入有权使用的观点，含交易员、方向、权重、因子、时间、到期时间。实时模式按有效观点加权汇总；过期排除。净方向权重绝对值显示为本站“置信度”分数，**不是成功概率**，不声称与原站算法相同。无观点时为空，不回退成历史数据。
- **TD**：通用Setup9＋非连续Countdown13，对向Setup9取消当前计数，第13根使用第8计数收盘的附加条件；不是经原站验证的私有TD算法。
- **指标参数**：行情后台可调趋势ATR周期／倍数、均量窗口／倍数、均线及趋势最少根数／幅度、放量幅度、大额监听成交额门槛；可关闭自动采集。参数保存后重新计算，初始基线不作为新信号提醒。
- 仍无法从原站网址恢复其服务端完整规则，也无法绕过其403或VIP权限获得未公开内容。实时全量扫描未完成时，结果只是已预热合约子集。

## 积分活动与应用

后台开启积分活动并设置参与成本、奖项积分与权重。前台沿用活动页，每账号上海日期每天一次。随机抽取在服务端完成，扣分、奖项、流水与参与次数在同一事务内完成，展示各奖项概率。仅积分奖励，没有实物库存、兑换履约、现金奖品或原站奖池。

网页增加PWA清单和网络断开页面，支持浏览器添加到主屏幕。**不缓存行情、账号接口或旧页面冒充在线数据。** 后台可填写管理员拥有的Android／iOS下载链接；本次未创建独立APK或上架App Store。
