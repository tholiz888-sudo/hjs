# 主站秘密花园栏目

入口位于主站左侧“秘密花园”，并在次导航提供手机入口。挂载在 `/crypto` 时地址为 `/crypto/garden`，独立运行门户时地址为 `/garden`。

进入后不加载门户的蓝色CSS或行情脚本，使用原站绿色背景、原始图片、文字排版和逐页背景音乐；只提供轻量的返回主站按钮。花园页面位于隔离框架中，原脚本不能操作主站账号或顶层页面。

资源在 `data/original`，清单为 `data/manifest.json`。4,870个成功采集文件全部纳入，包括163首MP3；音频支持流式Range播放。访问 `/crypto/garden/view/api/health` 可核对导入数量。

已知缺失：13个原站/meng/音乐地址返回404；部分历史失效图片/链接；原站ASP留言提交与验证码不再使用，新的留言板使用本站账号与审核流程。Flash已接入本地Ruffle兼容播放；Java旧插件改用Canvas实现，原图缺失时会明确标记待补齐。保留已取得的历史留言，禁止提交回原站，不用其他音乐冒充缺失曲目。

本栏目不修改现有投研、交易复盘、CMS或账号接口，也不建立新的付费云服务。主站沿用 main 分支和原来的启动命令。

## 后台内容管理

主站后台 `/crypto/admin#garden` 提供：原页面搜索与分页、保留HTML排版的覆盖编辑、新篇发布、草稿与回收站、栏目启用与排序、163首原音乐选择、已有图片搜索及2MB以内图片上传。新篇和原页面修改立即从数据库读取，无需重新部署。草稿、停用栏目及回收内容不会公开；预览接口也要求管理员登录。

原始采集文件不覆盖。编辑内容与栏目保存在主站内容数据库；上传图片位于该数据库旁的garden-media目录。现有主站JSON备份包含花园编辑和栏目，不包含图片文件。旧版主站备份恢复时不会清空花园内容。

公开HTML统一转换为UTF-8并清理原站域名、外链及备案号，保留内部跳转和返回主站。原始资料仍原样保留。页面与预览均使用CSP沙箱，原页面脚本不能取得主站同源权限。

测试：`node --test crypto-site/tests/garden-management.test.cjs crypto-site/tests/garden.test.cjs`；浏览器实际操作：`node crypto-site/tests/garden-browser.mjs`（需要已有Playwright与Chromium）。

## 旧特效兼容

- 飘雪脚本替换为requestAnimationFrame动画，不执行原脚本中的旧广告代码。
- 已采集的15个Flash页面使用同站自托管Ruffle 0.7.1（MIT/Apache-2.0），原SWF保留；不要求安装Flash。运行包来源与完整性在compat/ruffle/SOURCE.json，许可证随包保存。
- 4个Java Applet页面按原参数尺寸实现雨、雪、湖面倒影和渐变，不再运行Java插件。这些不是原Java字节码的逐指令模拟。
- 点击烟花在原背景和OGG资源未补齐时使用Canvas交互实现；资源齐全后自动恢复原始H5引擎。
- 原采集遗漏的/welcome/java下6张Applet图片、烟花背景与3个OGG音效共10项，已于2026-10-24从用户补采包校验后纳入清单；烟花现在使用原始H5引擎及原音效。补采工具保留于tools/effect-assets-helper.zip。
- Flash使用同源公共资源CORS，框架继续保持不允许同源身份的沙箱；主站私有接口不开放CORS。播放器外链操作关闭。
- 测试node --test crypto-site/tests/garden-effects.test.cjs；浏览器验证node crypto-site/tests/garden-effects-browser.mjs。

## 留言板与花园用户

花园外层右上角提供“留言板 · 登录／注册”，地址为 `/crypto/garden/community`（独立门户为 `/garden/community`）。沿用本站投研账号和加密密码验证；花园注册和登录会建立花园成员记录，不复制密码。登录cookie作用域与主站后台一致，退出时注销服务器会话并清理旧作用域cookie。原资料隔离框架不增加同源权限，新的留言页禁止嵌入框架。

后台“应用后台 → 秘密花园后台”增加“留言板管理”和“注册用户”：留言支持搜索、状态筛选、分页、审核公开、园主回复、隐藏、回收及恢复；用户支持搜索、分页、来源、邮箱、注册／加入时间、最近花园登录、留言数和花园禁言。已有账号首次从花园进入会记录为已有账号；不会将其他应用所有用户冒充花园注册用户。禁言仅禁止花园新留言，不封禁其他应用账号。

新留言须登录、每账号30秒限流、2000字以内，默认待审核；前台只显示已公开留言、昵称、时间与回复，不公开邮箱或用户ID，正文与回复作为纯文本显示。审核与用户管理接口要求现有管理员权限，写操作验证请求来源并记录操作日志。注册登录沿用本站频率限制。成员与留言存放在现有内容SQLite数据库的garden_members和garden_messages表；账号仍保存在现有账号数据库。历史留言从617个存档页面提取并去重后逐条导入（10453条），支持正文／标题编辑、回复、隐藏、回收和恢复；不建立虚构的历史注册账号。219条审核／私密占位记录不含原文，禁止公开或伪造正文。导入按稳定ID执行INSERT OR IGNORE，后台修改和回收不会因重启被覆盖。现有内容JSON备份不包含花园成员／留言表，完整保留需同时保存内容与账号数据库。

验证：`node --test crypto-site/tests/garden-community.test.cjs`；实际页面流程：`node crypto-site/tests/garden-community-browser.mjs`。

旧留言入口 `/garden/view/liuyan/`、`default.asp` 与 `index.asp` 均由可管理的留言数据生成，保留原横幅、橙色标题栏、头像与背景。目录路径不再返回缺失资源页。“签写留言”及旧的#nicheng锚点会进入可填写的本站表单；隔离框架通过只接受当前子框架的固定导航消息打开表单，不授予旧脚本同源或账号访问权限。新版与旧版入口共用同一留言数据，后台修改立即影响两处前台显示。原始HTML只作存档，不再用于公开留言列表。历史导入脚本为tools/import-guestbook.py，解析过程中只提取可见标题、昵称、正文、时间和头像，不导入IP、邮箱或假注册信息。

## 留言板接口失败时的可用性

社区页面的账号表单、当前登录状态、已公开留言与分页均由服务器直接输出，不先请求前台session接口；账号读取异常时仍输出登录表单和独立的留言列表。登录、注册、退出、提交使用本站普通POST表单，完成后303跳转，失败时显示中文原因。页面不再使用fetch加载关键表单或提交留言；关闭JavaScript也可使用。现有JSON API保留，管理员权限、登录校验、请求来源检查、留言审核与频率限制保持一致。浏览器回归包含拦截全部社区JSON API请求，以及关闭JavaScript后注册并提交留言。
